# **1. Project Overview**

## **1.1 Project goals**

This project is a **CLI tool that reimplements Git's core features in pure Java**.

Its goal is to implement Git's internal structures and behavior directly, as follows.

- **Implement Git's internal object model directly**
- Define Blob / Tree / Commit / Ref / Index as domain objects to reproduce how Git manages file snapshots and history.
- Aim for immutability in each domain and perform thorough validation at creation time.
- **Implement a filesystem-based Git repository**
- Just as Git stores metadata in a .git directory, this project creates a **.javaGit directory** serving the same role.
- Store Git objects based on **SHA-1 hashes**.
- Clearly separate each layer (Controller / Service / Repository / Domain) to support **understanding Git from an architectural perspective**.

## **2.2 Core Git domain model**

Git's internal concepts are modeled simply using the following domain objects.

<p align="center">
  <img src="/images/velog/우아한-테크코스-8기-오픈미션-보고서-20.webp" width="60%">
</p>

### **Blob**
- Holds file contents as byte[].
- Rejects null/empty arrays and maintains immutability through defensive copying.

### **Tree**
- A directory snapshot with a Map<String, String> (path → blob SHA) structure.
- Rejects null/empty keys and values, and makes the internal Map unmodifiable.

### **Commit**
- Contains message, treeOid, parentOid, author, and createdAtMillis.
- Validates required values (message, treeOid, author) at creation, then is serialized as text and stored in .javaGit/objects.

### **Index**
- The staging area: a Map<String, String> (path → blob SHA).
- git add populates this map, and git commit converts it into a Tree.

### **Head**
- A reference to the currently checked-out branch (e.g., refs/heads/master).
- Corresponds one-to-one with the .javaGit/HEAD file.

![](/images/velog/우아한-테크코스-8기-오픈미션-보고서-21.webp)

## **2.3 .javaGit storage structure and Repository summary**

**.javaGit** implements a structure similar to Git's .git.

### **Directory/file structure**
- .javaGit/objects/aa/bb...: Object files are stored by splitting their SHA-1 hash into the first two characters and the remainder.
- .javaGit/index: A text file containing Index state, with each line in the form <sha> <path>.
- .javaGit/HEAD: The current branch reference, such as ref: refs/heads/master.
- .javaGit/refs/heads/<branch>: A file containing the branch HEAD commit SHA.

### **Repository responsibilities**
- FileObjectWriter: Hashes a byte array using SHA-1, stores it in objects, and returns the hash string.
- FileObjectReader: Reconstructs raw bytes, Blob, Tree, and Commit from a hash.
- FileIndexRepository: Converts between .javaGit/index and the Index domain object.
- FileRefRepository: Reads and writes HEAD/branch refs as strings.

## **2.4 Command flow overview (input → domain/storage)**

All commands follow the common flow **“CLI input → GitController → Command Handler → Service → Repository/Domain → OutputView”**.

### **Input handling**
- In console mode, GitController.runConsole() reads a line and tokenizes it with a regular expression.
- After checking that the first token is "git", the remaining tokens are used as the command arguments.
- run(String[] args) receives arguments and delegates to the appropriate Command Handler through dispatch(args).

### **Main command flows**
#### git init
- InitService → FileSystemInitService creates the .javaGit directory and the HEAD, refs/heads/master, and index files.

#### git add
- AddService reads files and stores Blobs through ObjectWriter → updates the Index Map → updates the index file through FileIndexRepository

#### git commit
- CommitService creates Index → Tree → Commit, stores them through ObjectWriter, and moves the branch HEAD to the new commit through FileRefRepository.

#### git status
- StatusService compares working-tree SHAs, the Index, and the HEAD Tree to calculate staged/modified/deleted/untracked states.

#### git log
- LogService follows the parent chain from HEAD, listing Commits in reverse order.
- git branch / git checkout / git merge
- BranchService, CheckoutService, and MergeService combine RefRepository and ObjectReader to create/switch branches and perform FF merges.

#### git push / git pull / git clone / git push-http / git pull-http
- Synchronize .javaGit/objects and refs through a filesystem remote (FileRemoteClient) or HTTP remote (HttpRemoteClient/Server).
- All **allow only fast-forward conditions**.

#### **Output**
- OutputView handles all success/failure messages and status/log output.

# **3. Internal Behavior of Main Features**

An outline of **the sequence and logic used inside this project** to handle features corresponding to actual Git commands

Most features follow the “Controller → Command Handler → Service → Repository/Domain” flow.

---

## **3.1 git init – Repository initialization**

#### **Purpose**: Initialize the current directory as a Git repository and create the .javaGit structure.

#### **Flow**
- GitController → InitCmd.execute(args) → InitService.init() → FileSystemInitService.initRepository(rootDirectoryPath)

#### **Main processing**
- Create the .javaGit directory
- .javaGit/objects
- .javaGit/refs/heads

#### Create files
- Write the default branch reference to .javaGit/HEAD: ref: refs/heads/master\n
- .javaGit/refs/heads/master: An empty string (no commits yet)
- .javaGit/index: Create an empty Index file

#### **Validation/exceptions**
- Throw REPOSITORY_INIT_FAILED if an IO error occurs while creating directories/files.

---

## **3.2 git add – File staging**

**Purpose**: Read changed files from the working tree, store them as Blobs, and record staging information (path → blob SHA) in the Index.

**Flow**
- GitController → AddCmd.execute(args) → AddService.add(List<String> filePaths)

#### **Main processing**
1. **Validate arguments**
- If filePaths == null or empty, throw an exception with ErrorCode.EMPTY_PATHS.

2. **Read the current Index**
- Read existing staging state through IndexRepository.read() and copy it into a LinkedHashMap.

3. **Process each file**
- Build an absolute path with rootDirectoryPath.resolve(filePath).
- Skip files that do not exist or are directories.
- Read contents with Files.readAllBytes → call ObjectWriter.write(byte[])
- FileObjectWriter computes the SHA-1 hash, stores the data in .javaGit/objects, and returns the hash.
- Update the Index Map with filePath → objectHash.

4. **Write the Index**
- Create a new Index domain object and update .javaGit/index through IndexRepository.write(index).

---

## **3.3 git commit – Finalizing a snapshot**

**Purpose**: Create Tree/Commit objects from the Index's staged contents and move the current branch HEAD to the new commit.

#### **Flow**
- GitController → CommitCmd.execute(args) → CommitService.commit(message, author)

#### **Main processing**
1. **Validate message/author**
- message == null || isBlank → COMMIT_MESSAGE_EMPTY
- author == null || isBlank → COMMIT_AUTHOR_EMPTY

2. **Read the Index and check whether it is empty**
- Obtain the Index through IndexRepository.read()
- If index.stagedFiles() is empty, throw a "Nothing to commit" exception

3. **Create and store the Tree**
- Create a Tree domain object with new Tree(index.stagedFiles())
- Generate a string in the "blob <sha> <path>\n" format with buildTreeContent(tree)
- Store the Tree object through ObjectWriter.write(treeContentBytes) → return treeHash

4. **Read the current HEAD commit**
- Get the current branch name through RefRepository.readCurrentBranch()
- Get the HEAD commit SHA through RefRepository.readBranchHead(branch)

5. **Create and store the Commit**
- Create new Commit(message, treeHash, parentHashOrNull, author)
- Generate commit text through buildCommitContent(commit)
- Store the commit through ObjectWriter.write(commitBytes) → return commitHash

6. **Update HEAD**
- Update the current branch HEAD to the new commit through RefRepository.updateBranchHead(branch, commitHash).

---

## **3.4 git status – Checking status**

**Purpose**: Compare the working tree, Index, and HEAD commit Tree to provide Git-like status information.

#### **Flow**
- GitController → StatusCmd.execute(args) → StatusService.status() → StatusResult

#### **Internal behavior**
1. **Scan the working tree**
- Traverse all files with Files.walkFileTree(rootDirectoryPath)
- Skip the .javaGit directory with SKIP_SUBTREE.
- For each regular file:
- Calculate its relative path (\ → /)
- Calculate the file contents' SHA-1 hash → store path → sha in Map<String, String> working
2. **Read Index and HEAD Tree snapshots**
- index = IndexRepository.read().stagedFiles()
- headTree = readHeadTreeSnapshot() (an empty Map if there is no HEAD commit)
3. **Compare the staging area (HEAD vs Index)**
- stagedAdded: Paths in the Index but not in HEAD
- stagedModified: Paths in both with different SHAs
- stagedDeleted: Paths only in HEAD
4. **Compare working tree vs Index**
- modifiedNotStaged: Paths in both with different SHAs
- deletedNotStaged: Paths in the Index but not the working tree
5. **Calculate untracked files**
- Classify paths in the working tree but not the Index as untracked
6. **Return the result**
- Return these six collections as a StatusResult record.

---

## **3.5 git log – Viewing commit logs**

**Purpose**: Start at the current branch HEAD and follow the parent chain to print commit history.

#### **Flow**
- GitController → LogCmd.execute(args) → LogService.list() → List<LogEntry>

#### **Internal behavior**
**1. Find the HEAD commit**

**2. Follow the parent chain:**
- ObjectReader.readRaw(commitHash) → parse commit text
- Read tree, parent, author, date, and message.
- Convert dateMillis into an ISO string.
- Take only the first line of the message for LogEntry.message.
**3. Collect all commits in a list and return it as an immutable list.**

---

## **3.6 git branch / git checkout – Managing and switching branches**

#### **git branch**
- BranchService.list() → return the result of RefRepository.listBranches().
- BranchService.create(name):
- Validate the name (no whitespace/slashes), then call createBranch using the current branch HEAD as the base.

#### **git checkout**
- CheckoutService.switchBranch(branchName):
- Check whether the branch exists.
- Use StatusService.status() to check that the working tree/staging area is clean.
- If clean, update .javaGit/HEAD through RefRepository.updateCurrentBranch(branchName).

---

## **3.7 git merge – Fast-forward merging**

**Purpose**: Merge another branch into the current branch **only when a fast-forward is possible**.

#### **Flow**
- GitController → MergeCmd.execute(args) → MergeService.merge(targetBranch)

#### **Main decision logic**
- If the target branch name/HEAD does not exist → BRANCH_NOT_FOUND
- If the current HEAD is empty → FF to target HEAD (FAST_FORWARD)
- If HEADs match → ALREADY_UP_TO_DATE
- Otherwise, check ancestry with isAncestor(currentHead, targetHead)
- If it is an ancestor → FF the current branch HEAD to the target HEAD
- Otherwise → NOT_FAST_FORWARD (no actual 3-way merge)

---

## **3.8 git push / git pull / git clone – Local-directory remotes**

#### **git push (filesystem remote)**

- PushService.push(remoteRoot, branch):
- Compare local/remote HEADs and check the FF condition.
- If satisfied, copy all of .javaGit/objects and update the remote branch HEAD to the local HEAD.

#### **git pull (filesystem remote)**
- PullService.pull(remoteRoot, branch):
- Check the remote HEAD and whether FF is possible.
- If possible, copy remote objects locally and move the local HEAD to the remote HEAD.

#### **git clone (filesystem remote)**
- CloneService.clone(remoteRoot, targetRoot):
- Check that the target directory is empty.
- Copy objects/refs/HEAD from the remote .javaGit to the target (without checking out the working tree).

---

## **3.9 git serve-http / git push-http / git pull-http – HTTP remotes**

#### **git serve-http**
- Start an HTTP server to handle refs/objects retrieval and updates.

#### **git push-http (HttpPushService)**
- Query the remote refs/objects state, upload only missing objects, then update the remote HEAD if FF is possible.

#### **git pull-http (HttpPullService)**
- Compare remote and local HEADs. If FF is possible, follow the commit chain to download the required commit/tree/blob objects, then move the local HEAD.

## **4.2 Domain-layer validation**

Domain objects perform strong constructor validation to ensure **immutability and consistency**.

#### **Blob**
- If byte[] is null → BLOB_FILE_NULL; if its length is 0 → BLOB_FILE_EMPTY
- Store a copy internally and return copies as well to protect against external modification.

#### **Tree**
- If the input Map is null → TREE_ENTRIES_NULL
- If an entry's path is null → TREE_ENTRY_PATH_NULL; if objectId is null → TREE_ENTRY_OID_NULL
- Copy internally and wrap in unmodifiableMap.

#### **Commit**
- message == null → COMMIT_MESSAGE_NULL; blank → COMMIT_MESSAGE_EMPTY
- treeOid == null → COMMIT_TREE_OID_NULL.
- author == null → COMMIT_AUTHOR_NULL; blank → COMMIT_AUTHOR_EMPTY

#### **Index**
- stagedFiles == null → INDEX_STAGED_FILES_NULL
- An entry's key/path is null → INDEX_STAGED_FILE_PATH_NULL
- value/OID is null → INDEX_STAGED_FILE_OID_NULL

#### **Head**
- refName == null → HEAD_REF_NULL
- Blank → HEAD_REF_EMPTY

## **4.3 Repository-layer exception handling**

Repositories form the **boundary between the filesystem and the domain**, so IO errors and format errors are handled distinctly.

#### **Index (FileIndexRepository)**
- Read failure → INDEX_FILE_READ_FAILED
- Write failure → INDEX_FILE_WRITE_FAILED

#### **Object (FileObjectWriter, FileObjectReader)**
- Failed to create the object directory → OBJECT_DIRECTORY_CREATE_FAILED
- Failed to write an object file → OBJECT_FILE_WRITE_FAILED
- Object file does not exist → OBJECT_FILE_NOT_FOUND
- Read failure → OBJECT_FILE_READ_FAILED
- Invalid Tree/Commit format → MALFORMED_TREE_OBJECT, MALFORMED_COMMIT_OBJECT

#### **Ref (FileRefRepository)**
- IO error while reading/writing HEAD or refs → FILE_IO_ERROR
- Empty or incorrectly formatted HEAD contents → HEAD_REF_EMPTY or HEAD_REF_NULL

---

## **4.4 Service-layer exception handling**

Services throw explicit exceptions for **business-rule violations** and **user-input errors**.

#### **AddService**
- Empty path list → EMPTY_PATHS
- File read failure → FILE_READ_FAILED

#### **CommitService**
- Message/author validation failure → COMMIT_MESSAGE_EMPTY, COMMIT_AUTHOR_EMPTY
- No staged files in the Index → "Nothing to commit" (explicit message)

#### **FileSystemInitService**
- Failed to create a directory/file → REPOSITORY_INIT_FAILED

#### **StatusService**
- Failed to read a working-tree file → FILE_READ_FAILED
- Failed to traverse the directory tree → FILE_IO_ERROR
- SHA-1 algorithm unavailable → SHA1_NOT_AVAILABLE

#### **Remote services**
- Wrap IO exceptions from filesystem or HTTP communication in IllegalArgumentException with the appropriate ErrorCode.
- Represent non-fast-forward push/pull outcomes using **result enums** (NOT_FAST_FORWARD, REMOTE_REJECTED_NON_FF), rather than exceptions.
